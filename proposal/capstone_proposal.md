# DSA 8401 Capstone Proposal (Draft)

**Title:** Explainable Temporal and Relational Anomaly Prioritisation of Kenyan Public Procurement Processes

### 1. Problem statement

Kenyan PPIP/OCDS records describe procurement processes through tender attributes, publication histories, buyer and supplier references, and tender text. These records are incomplete and unevenly disclosed, while verified audit, sanction and court outcomes cover only a subset of activity. A process-level row model may overlook repeated buyer–supplier patterns and changes over time; a model that uses future award or audit information at tender time would also produce misleading results. This project will develop a reproducible screening system that ranks procurement processes for human review using only evidence available at the scoring timestamp. A score will indicate statistical review priority, not prove fraud or corruption.

### 2. Data source

The primary source is the Public Procurement Regulatory Authority's PPIP publication in the Open Contracting Data Standard (OCDS), available through the PPIP portal and Open Contracting Partnership data registry. The registry profile retrieved in November 2026 describes publication coverage from July 2018 to October 2026 and reports substantial tender, award, contract and party records, but also data-quality limitations including no reported tenderer objects, missing organisation-identifier schemes and incomplete lifecycle fields. The source export will be frozen, hashed and profiled before modelling. If the available download contains immutable release histories, scoring will be reconstructed at tender publication; if only compiled releases are available, the research task will be explicitly limited to latest-state review and will not be described as tender-time early warning. The precise eligible process count and field completeness will be established from the downloaded snapshot rather than assumed from registry totals. Supplementary official audit or sanction findings will be used only if access, provenance and linkage to a process or supplier are defensible.

### 3. Planned approach and serving design

A scripted OCDS pipeline will validate and deduplicate releases, construct one first-tender observation per OCID, preserve missingness, and build historical buyer and supplier-concentration features from publications strictly earlier than the scoring time. Tender text will be represented with TF-IDF; structured attributes will be processed with training-only imputation, scaling and categorical encoding. Isolation Forest will provide an unsupervised anomaly-ranking baseline. If sufficient independently verified positive findings and a justified class prior exist, a non-negative positive-unlabelled learner will be tested without treating unlabelled cases as negatives. Baselines and ablations will be compared using chronological holdout and, where entity/label coverage permits, buyer- and supplier-disjoint tests. Ranking and observed-positive retrieval metrics will be reported with limitations. A bidder-group hypergraph feature will be enabled only if complete tenderer identities are present; it is not assumed from awarded-supplier data.

The trained preprocessing and model will be serialised together, served through FastAPI `/score`, and packaged in a non-root Docker container. The API will return a priority percentile, evidence trace, data-confidence note and human-review caveat. KS/PSI monitoring will check input drift. All configuration, data hashes, seeds and software versions will be recorded.
